# CodeHogwarts — гайд по проекту

Короткая карта: что это, на чём написано, где что лежит и как оно работает.
Читается за десять минут, дальше можно возвращаться к нужному разделу.

**Живой стенд:** https://maks.my/codehog/

---

## 1. Что это

Тренажёр Python в виде игры. Человек заходит без регистрации, отвечает,
программировал ли раньше, проходит тест на шесть вопросов, получает курс под
свой уровень и решает задания прямо в браузере. Код не проверяется по образцу,
а **реально исполняется на сервере**. За пройденные уроки начисляются монеты,
каждые пять уроков даётся вращение колеса, на монеты покупаются скины ежа.

Скинов 54: шесть уровней по девять. Первый уровень открыт сразу, из него при
регистрации бесплатно выбирается стартовый ёж. Каждый пройденный модуль курса
открывает следующий уровень.

Смысл в одной фразе: **выполненный код превращается в коллекцию ежей.**

## 2. На чём написано

| Слой | Технология | Зачем именно она |
|---|---|---|
| Сервер | Python 3.14 + FastAPI | Приложение учит Python и запускает код учеников. На той же платформе это делается штатными средствами |
| Схемы API | Pydantic | Описывают JSON запросов и ответов. FastAPI по ним проверяет входные данные и строит документацию |
| Работа с базой | SQLAlchemy 2.0 | ORM: таблицы описаны классами, SQL руками не пишется |
| База | SQLite | Один файл. Доступ только через ORM, переезд на PostgreSQL меняет строку подключения |
| Страницы | Jinja2 | HTML собирается на сервере и приходит готовым |
| Клиент | Ванильный JavaScript | Семь файлов, около 500 строк. Ни React, ни npm, ни сборки |
| Пароли | bcrypt | Хранятся только хэши |
| Сессии | itsdangerous | Подписанная cookie, подделать нельзя |
| Нейросеть | OpenAI-совместимый шлюз | Генерация уроков и подсказок. Модель `deepseek-v4-flash` |
| Журнал | logging + journald | Время, уровень, адрес запроса, пользователь и стек каждого сбоя |
| Развёртывание | systemd + nginx | Свой сервер, HTTPS |

**Ванильный JavaScript** значит «чистый, без фреймворка». Браузер получает
файл и сразу исполняет. Ничего не нужно собирать перед выкладкой.

## 3. Как устроено

Запрос идёт сверху вниз, каждый слой знает только соседний.

```
браузер
   │  HTTPS
nginx ──────── отдаёт картинки и стили прямо с диска
   │  остальное проксирует
FastAPI
   │
api/       ── принимает запросы, отдаёт HTML или JSON
   │           знает про HTTP, не знает про бизнес-правила
   │           форма JSON описана Pydantic-схемами в schemas.py
services/  ── бизнес-логика: монеты, серии, песочница, генерация уроков
   │           не знает, что существует HTTP
models/    ── описание таблиц
   │
SQLite
```

Правило простое: `services` никогда не импортирует FastAPI, а `models`
никогда не импортирует `services`. Поэтому логику можно проверять без
поднятия сервера.

Отдельно в стороне стоят две вещи:

- **песочница** — отдельный процесс, в котором исполняется код ученика;
- **шлюз нейросети** — внешний сервис, к которому ходят за уроками и подсказками.

## 5. Механизмы, которые стоит понимать

### Исполнение кода ученика

Код не разбирается и не сравнивается с образцом. Он **запускается**
в отдельном процессе с тремя ограничениями: не дольше пяти секунд, не больше
128 мегабайт памяти, не больше десяти тысяч символов вывода. Процесс стартует
без доступа к переменным окружения и в пустом временном каталоге. Результат
возвращается через служебную метку в выводе.

Перед запуском код проходит грубую проверку на запрещённые модули и вызовы.
Это не полноценная изоляция, и в документации это признано прямо: для
публичного сервиса нужен контейнер без сети.

### Проверка сгенерированных уроков

Самая ценная идея в проекте. Нейросеть выдаёт урок вместе с эталонным
решением и тестами. Прежде чем урок попадёт к ученику, **эталонное решение
запускается в песочнице против этих же тестов**. Не сошлось — урок
отбрасывается целиком и берётся шаблонный.

То есть враньё модели физически не доезжает до пользователя.

Первый урок курса и оба вводных модуля написаны вручную
(`services/ready_lessons.py`) и модели не отдаются: первый урок должен
открываться мгновенно, а новичкам нужны выверенные задания.

### Экономика через одну точку

Любое изменение баланса проходит через один метод. Он записывает строку
в журнал операций и запрещает уйти в минус. Поле с балансом существует
только ради скорости чтения: настоящий баланс всегда можно пересчитать
суммой по журналу и сверить.

### Защита от двойных начислений

Двойной клик по колесу или две открытые вкладки не дают приз дважды.
Работает не проверка в коде, а **уникальное ограничение в базе** на пару
«пользователь и веха». Второй запрос упирается в него и отваливается.
Проверку в коде можно обойти параллельным запросом, ограничение базы нельзя.

Так же защищены медали и задания внутри урока.

### Путь новичка

Перед тестом один вопрос: программировал ли раньше. Три ответа — три пути:

| Ответ | Что происходит |
|---|---|
| Никогда | Тест пропускается, уровень «новичок», курс начинается с модуля «Что такое программа» |
| На другом языке | Тест проходится, а в курс первым встаёт модуль «Python после другого языка» |
| На Python | Обычный тест и курс по его итогам |

Ответ хранится в `test_attempts.experience`, вводные модули описаны в
`services/curriculum.py`.

### Скины по уровням

У каждого скина в таблице `items` есть поле `tier` — номер уровня. Открытый
уровень не хранится, а считается: один плюс число полностью пройденных
модулей. Поэтому его нельзя «сломать» рассинхронизацией. Купить скин закрытого
уровня нельзя: отказ идёт из `economy.py`, а не только из интерфейса.
Старая одежда не удалена из базы, а выключена флагом `is_active`, чтобы не
потерять историю покупок.

### Журнал ошибок

Любое необработанное падение перехватывает middleware в `main.py`. В журнал
пишется время, адрес запроса, ID пользователя и полный стек, а пользователь
видит короткое сообщение и кнопку «Повторить» (`static/js/errors.js`). Стек
наружу не уходит. Смотреть журнал на сервере: `journalctl -u codehog`.

### Работа без нейросети

Убери ключ из настроек, и приложение продолжит работать: уроки станут
шаблонными, подсказки статичными, всё остальное не изменится. Внешний
сервис не является точкой отказа.

## 6. Как здесь используется FastAPI

Сайт отдаёт два вида ответов, и для каждого FastAPI применён по назначению.

**Страницы** (`api/pages.py`) — HTML из шаблонов Jinja2. Поля форм регистрации
и входа объявлены как `Annotated[str, Form()]`, после отправки идёт редирект. Это
классический серверный рендеринг, FastAPI его поддерживает штатно.

**JSON API** (`api/actions.py`, префикс `/hog`) — то, к чему ходит JavaScript:
тест, проверка заданий, подсказки, колесо, магазин. Здесь всё, ради чего
FastAPI задуман:

- **Pydantic-схемы** (`api/schemas.py`). Тело запроса объявлено классом,
  например `TaskAnswer`. Неверный JSON отклоняется с кодом 422 ещё до нашего
  кода, а ответ описан через `response_model` — наружу уходят только
  объявленные поля.
- **Зависимости** (`Depends` в стиле `Annotated`). В `api/deps.py` объявлены
  типы `SessionDep`, `CurrentUser`, `RequiredUser`, `GuestToken`, в админке —
  `AdminUser`. Ручка просто пишет `user: RequiredUser`, и FastAPI сам достаёт
  пользователя или отвечает 401. Проверка входа не копируется в каждую функцию.
- **Автодокументация.** Swagger со всеми схемами открывается по адресу
  https://maks.my/codehog/hog/docs. Ручки разбиты по тегам: test, lessons,
  wheel, shop.
- **Lifespan.** Подготовка базы при старте сделана через `lifespan`,
  а не через устаревший `on_event`.
- **Обработчики исключений.** Ошибка проверки данных, отказ «не хватает
  монет» и неожиданный сбой приходят в одном формате `{"detail": "..."}`.

### Стиль кода

Весь код — Python, JavaScript, CSS, шаблоны — написан по-английски: имена
переменных, функций, классов, CSS-классы, комментарии и docstring. Русский
остаётся только в текстах, которые видит ученик, и в документации.

Python оформлен по PEP 8 и проверяется линтером `ruff`, настройки — в
`pyproject.toml` (длина строки 99, как PEP 8 разрешает команде). Проверить
и отформатировать:

```bash
ruff check app docs     # стиль, имена, неиспользуемые импорты, типичные ошибки
ruff format app docs    # единое форматирование
```

## 7. Как запустить и выкатить

Локально:

```bash
./run.sh                      # поднимет окружение и запустит
```

Откроется на `http://127.0.0.1:8000/codehog/`. Подкаталог задаётся
переменной `BASE_PATH` в файле `.env`.

На сервер:

```bash
rsync -az --delete --exclude '.venv' --exclude 'data' --exclude '.env*' \
  --exclude '.git' --exclude '__pycache__' ./ root@maks.my:/opt/codehog/
ssh root@maks.my 'chown -R www-data:www-data /opt/codehog && systemctl restart codehog'
```

Схема базы обновляется сама при старте (`services/migrate.py`), отдельных
миграций запускать не нужно. Перед выкладкой стоит скопировать файл базы:
`cp data/codehog.db data/codehog-$(date +%F).db`.

| Надо сделать | Файл |
|---|---|
| Изменить награды за урок или цены | `services/economy.py`, `services/seed.py` |
| Добавить скин или уровень | картинка в `static/img/skins/`, строка в `services/seed.py` |
| Поменять правило открытия уровней | `services/economy.py` — `unlocked_tier` |
| Добавить поле в JSON-ответ | `api/schemas.py`, затем `api/actions.py` |
| Заменить логотип | `static/img/logo/` |
| Добавить тему в курс | `services/curriculum.py` |
| Поправить готовый урок | `services/ready_lessons.py` |
| Изменить, что генерирует нейросеть | `services/course.py` — промпт и проверка |
| Добавить тип задания | `models/learning.py`, `services/course.py`, `api/actions.py`, `templates/lesson.html` |
| Добавить медаль | `services/awards.py` — каталог наверху файла |
| Заменить подборку мемов | картинки в `static/img/memes/`, список в `services/awards.py` |
| Добавить язык | `services/i18n.py` |
| Поменять внешний вид | `static/css/style.css` — токены в начале файла |
| Пересобрать схему базы для документации | `docs/build_schema.py` |
| Пересобрать документ в Word | `docs/build_docs.py` |

## 9. Что честно не сделано

1. **Автотестов нет.** Проверки ручные и скриптами, воспроизводимые,
   но `pytest` это не заменяет.
2. **Изоляция кода процессная, не контейнерная.** Для учебного стенда
   достаточно, для публичного сервиса мало.
3. **Раздела CMS нет.** Уроки и скины задаются в коде, хотя медали
   и мемы уже вынесены в таблицы.
