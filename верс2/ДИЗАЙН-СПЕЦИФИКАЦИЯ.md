## 1. Концепция

**CodeHog — гараж прокачки: выполняемый код превращается в видимые улучшения кибер-ежа.**

| Отталкиваемся от | Как выражаем | Избегаем |
|---|---|---|
| Персонажа, которого пользователь развивает | Один крупный ёж на платформе; состояния — ступени одного прогресса | Трёх равнозначных рекламных карточек |
| Реального запуска Python | Код, результат выполнения, подтверждение проверки | Декоративного «хакерского» текста |
| Гаража и интерфейса оборудования | Графитовые поверхности, маркировка, короткие соединительные линии | Неонового города, стекла, бесконечных свечений |
| Игровой награды | Янтарные монеты и предметы; бирюзовый — действие и энергия | Интерфейса, где каждый элемент пытается быть наградой |

Это язык именно CodeHog: **код — причина, изменение персонажа — следствие**. Не «курс с маскотом», а тренажёр с видимой отдачей.

## 3. Типографика

**Golos Text** — весь интерфейс и заголовки. **JetBrains Mono** — код, номера этапов, технические метки. Оба доступны через Google Fonts и поддерживают кириллицу.

| Роль | 1440 px: размер / строка | 390 px: размер / строка | Вес |
|---|---:|---:|---:|
| Hero H1 | `56 / 60 px` | `32 / 36 px` | `700` |
| H2 | `36 / 40 px` | `28 / 32 px` | `700` |
| H3 | `24 / 30 px` | `20 / 26 px` | `600` |
| Вводный текст hero | `18 / 26 px` | `16 / 22 px` | `400` |
| Основной текст | `16 / 24 px` | `16 / 24 px` | `400` |
| Кнопки | `16 / 20 px` | `16 / 20 px` | `600` |
| Подписи | `14 / 20 px` | `14 / 20 px` | `400` |
| Технические метки | `12 / 16 px` | `12 / 16 px` | `500`, Mono |
| Код | `14 / 22 px` | `14 / 22 px` | `400`, Mono |

- Трекинг H1: `-1 px` на desktop, `-0.4 px` на mobile.
- Остальной текст: `0 px`. Капитель — только в коротких технических метках.
- Цифры прогресса и монет: `font-variant-numeric: tabular-nums`.

### Заголовок — управляемая композиция

На обеих ширинах:

> Освой Python.  
> Прокачай  
> кибер‑ежа.

Три строки здесь намеренные: третья строка целиком называет объект прокачки. Не пытаться случайно уместить всё в две.

```css
.hero-title {
  hyphens: none;
  word-break: normal;
  overflow-wrap: normal;
}

.hero-title__line {
  display: block;
}

.hero-title__character {
  white-space: nowrap;
}
```

В `кибер‑ежа` использовать **неразрывный дефис U+2011**. Не применять `word-break: break-all` к русскому интерфейсу. Длинные технические строки прокручиваются внутри своего контейнера, а не раздвигают страницу.

## 5. Пять узнаваемых приёмов

| Решение | Исполнение | Как помогает клику |
|---|---|---|
| **Персонаж на платформе прокачки** | Один крупный объект, три стадии под ним | За один взгляд объясняет, что именно пользователь будет развивать |
| **Код рядом с физическим результатом** | Небольшая плашка выполнения пересекает сцену, но не закрывает лицо и худи | Отличает продукт от квиза и видеокурса |
| **Единый маршрут вместо ряда карточек** | Номера, соединения, разные пиктограммы | Объясняет, зачем проходить тест и что будет после |
| **Монеты — отдельный цветовой канал** | Янтарный только у заработка и покупок; CTA бирюзовый | Награда заметна, но не конкурирует с входом в продукт |
| **Собственный знак CodeHog** | Геометрический ёж с тремя иглами и одной дорожкой платы | Связывает название с персонажем без зависимости от эмодзи |

### Логотип

- Знак строить в сетке **32 × 32 px**.
- Три верхние иглы; корпус — единый силуэт; внутри одна дорожка толщиной **2 px** с контактом **4 × 4 px**.
- Слово `CodeHog`: Golos Text **24/28 px**, вес **700**, расстояние до знака **8 px**.
- Знак `#35E0A1`, слово `#F2F5EF`.
- Для favicon сделать отдельную версию **16 × 16 px** без внутренней дорожки.
- Не копировать силуэт головы, обувь или графику бренда Sonic: узнаваемость строить на **иглах-платах и собственных пропорциях ежа**.

### Варианты ответа в тесте

| Параметр | Решение |
|---|---|
| Размер | Минимальная высота `64 px`; padding `16 px`; gap между вариантами `12 px` |
| Структура | Radio `20 px` + текст; на desktop справа номер клавиши |
| Обычное состояние | `#192228`, граница `1 px #657781` |

| Hover | `#28373F`; выбранное состояние не теряет бирюзовую границу |
| Поведение | Нажатие выбирает, но **не переводит автоматически** к следующему вопросу |
| Переход | Отдельная кнопка «Дальше»; «Не знаю» — самостоятельный вариант, не ошибка |
| Высота | Растёт с текстом; не обрезать русские ответы до одной строки |

### Редактор и консоль

| Элемент | Конкретное решение |
|---|---|
| Оболочка | Фон `#0B1013`; радиус `12 px`; border `1 px #2D3B43` |
| Верхняя панель | Высота `44 px`; вкладка `main.py`; справа статус среды |
| Редактор | JetBrains Mono `14/22 px`; gutter `48 px` desktop, `36 px` mobile; padding-y `16 px`; табуляция `4` пробела |
| Подсветка | Основной код `#DCE5EA`; keywords `#C5ACFF`; строки `#E8C47A`; числа `#94BDFF`; функции `#63EBB9`; комментарии `#899AA4` |
| Текущая строка | `#15232B`; выделение `#234B5D` |
| Запуск | Кнопка «Запустить» `48 px`; `Ctrl+Enter` / `Cmd+Enter`; рядом отдельная «Проверить» |
| Во время запуска | «Выполняется…»; повторный запуск блокируется; статус основан на реальном ответе среды |
| Консоль | Заголовок `40 px`; desktop высота по умолчанию `176 px`, минимум `128 px`; разделитель с зоной захвата `8 px` |
| Вывод | Обычный `#DCE5EA`; stderr `#FF8694`; traceback сохраняется с переносами строк |
| Проверки | «Пройдено 3 из 4» + отдельные результаты; успешный `print` не означает решение задачи |
| Начисление | Только после подтверждённого выполнения условий задачи; не за каждый запуск и не повторно за то же решение |

Редактор, консоль и реальная проверка должны быть визуально разными областями. Иначе пользователь не понимает разницу между «код запустился» и «задача решена».
